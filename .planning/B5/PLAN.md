# B5 — Plan

## 1. Goal and user-visible result
B5 adds `commit-kind classify` and rewrites the README. Milestone 1 is done when B5 is merged and `./scripts/check.sh` is green on `main`. B5 starts on `main` after B4 merges.
- `commit-kind classify "fix: handle empty input"` prints `fix`. With `--json` it prints `{"evidence": "fix:", "label": "fix", "rule": "prefix.fix"}`. With `--explain` it prints one line, e.g. `fix because the Conventional Commit prefix "fix:" matched (rule prefix.fix)`.
- `commit-kind classify -` reads all of stdin as one message.
- Exit codes: 0 ok, 1 empty message, 2 usage error. Errors go to stderr, stdout stays empty.
- **Budget:** at most about 60 added lines in `cli.py`, about 80 lines of tests, about 90 lines of README. No new flags beyond these, no new API in B4.

## 2. Interfaces and file ownership (what other blocks may touch, what they must not)
| File | B5 does |
|---|---|

| `tests/test_classify_cli.py` (new) | end-to-end and explain tests |
| `tests/sitecustomize.py` (new, 2 lines: `import _netguard` / `_netguard.install()`) | network guard for child processes (backlog `20261025-subprocess-netguard`) |

| `evals/config.json`, `evals/baseline.json` | only via `eval --write-baseline --block B5` |
| `.planning/backlog/20261025-subprocess-netguard.md` | sets `status: done` |

- **Must not touch:** `classifier.py`, `rules.py`, `strategies.py`, `evaluate.py`, `data/`, `scripts/`, `pyproject.toml`. `STATE.md` belongs to the orchestrator.
- **Uses B4 as merged:** `classify`, `Classification`, `EmptyMessageError`, and `rules.RULES` (`id`, `kind`).
- **How explain works:** look up the kind with `{r.id: r.kind for r in RULES}`, then the phrase from `KIND_TEXT`. An unknown kind falls back to `rule "<evidence>" matched`.
- **The five phrases:**
  - prefix: `the Conventional Commit prefix "<e>" matched`
  - verb: `the leading verb "<e>" matched`
  - ambiguous: `the verb phrase "<e>" matched`
  - object: `the object word in "<e>" matched`
  - fallback: `no rule matched, so the fallback applies`
- **Input and output:**
  - stdin is read as `sys.stdin.buffer.read().decode("utf-8", "replace")`, so there is no traceback on bad bytes.
  - `--json` and `--explain` are a mutually exclusive argparse group, so using both is exit 2.
  - JSON output is `json.dumps(asdict(c), sort_keys=True)`, ASCII-escaped.
  - `EmptyMessageError` prints `classify: error: <msg>` to stderr and returns 1.
- **Child guard:** child processes get `PYTHONPATH=src<pathsep>tests`, so `tests/sitecustomize.py` loads at startup and blocks sockets. The pytest process itself is not affected, because `pythonpath` is added after startup.

## 4. Tests (name — what it proves; include error paths and one negative control per metric)
All subprocess tests use one helper: `sys.executable -m commit_kind`, `cwd` the repo root, `PYTHONPATH=src<pathsep>tests`, `timeout=30`.
- `test_label`: `classify "fix: handle empty input"` gives stdout `fix\n`, rc 0, empty stderr.
- `test_json`: `json.loads(stdout) == asdict(classify(msg))`, and the keys are exactly label, rule, evidence.
- `test_explain`: exactly one line, containing the rule id and the evidence.
- `test_stdin_is_one_message`: `docs: reword the intro\n\nBody.\n` on stdin gives the single line `docs`.
- `test_empty_exit_1` (parametrized): `""`, `"   "`, and empty stdin with `-` each give rc 1, empty stdout, and `empty` in stderr.
- `test_usage_exit_2` (parametrized): no message, `--json --explain x`, and `--bogus x` each give rc 2, `usage:` in stderr, empty stdout.
- `test_explain_knows_every_kind` (in-process): every `r.kind` in `RULES` has a `KIND_TEXT` entry. This guards against B4 drift.
- `test_child_network_blocked`: `-c "import socket; socket.create_connection(('127.0.0.1', 9))"` gives rc ≠ 0 and `network access is blocked` in stderr. This is the negative control for the guard.

## 5. Acceptance criteria (checkable by a machine or in five clicks)
1. `PYTHONPATH=src python3 -m commit_kind classify "fix: handle empty input"` prints `fix`, rc 0.
2. `--json` gives exactly the 3 keys. `--explain` gives 1 line containing `prefix.fix`. The stdin example from section 4 prints `docs`.
3. `classify ""` and `printf '' | ... classify -` give rc 1, stdout empty, stderr `classify: error: ...`. `classify` alone and `classify --json --explain x` give rc 2.
4. `./scripts/check.sh`: 5 PASS, `check passed`, rc 0. `eval` rc 0 with numbers unchanged from B4.
5. Size: `git diff --numstat main...loop/B5` shows ≤ ~60 added lines in `cli.py`, ≤ ~80 in the tests, and `wc -l README.md` ≤ 90.
6. `grep -c` finds in the README: the skill link, `synthetic`, `dev`, `.planning/B2/REVIEW.md`. Every README output block matches a fresh run.
7. `git diff --stat main...loop/B5` touches only the section 2 files. The hygiene scans (local paths, e-mail addresses, session links) are clean. Author and trailer follow hard rule 6.

- **README output goes stale** after later rule changes. Accepted; the reviewer re-runs the examples.
- **A user's own `sitecustomize`** is shadowed in test children only.
- **Rollback:** revert per step on the branch. After the merge, `git revert -m 1 <merge>`, which also removes B5 from `finished_blocks`. Never `--force`.

Decisions I made:
- **Stdin is one message**, not split on blank lines (roadmap simplified). Commit bodies contain blank lines, so splitting would cut one message into several. This drops `--single`.
- **Default output is the bare label**, which is easy to use in scripts.
- **`--json` and `--explain` are mutually exclusive.**
- **Explain is built in the CLI** from the rule kind and the evidence. No change to B4.
- **Netguard backlog item taken.** It is 2 lines, reuses `_netguard`, and needs no mypy path change.
- **README is haiku**, because it is docs from the outline above; the opus review checks the honesty claims.
- **The baseline is rewritten on the branch for B5** with unchanged numbers (definition of done 3).
