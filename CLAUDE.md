# commit-kind

A small Python CLI and library that classifies git commit messages by type (`feat`, `fix`, `docs`, `refactor`,
`test`, `chore`) with a transparent, rule-based classifier. Every prediction names the rule that produced it.
This repo is also a public example of the gated build loop: `.planning/` (roadmap, plans, summaries, review gates)
is part of the deliverable and stays in the repo.

## Hard rules (never break)

1. No secrets in code, logs, tests, commits. Only `.env` (git-ignored), and this project needs none.
2. No real personal data. The dataset is synthetic, generated by a script with a fixed seed. No messages, names or
   e-mail addresses from real repositories. No absolute local paths (they contain user names) in committed files.
3. No network access in tests or evals. The test suite blocks sockets; nothing may download data at runtime.
4. Every eval ships negative controls (majority class, keyword spam, random). Each control must fail every gated
   metric; if one passes, the metric is too lenient and the eval exits non-zero.
5. Ideas outside the current block go to `.planning/backlog/`, not into code.
6. Public repo, anonymous: commits as `michaelt-45 <202262075+michaelt-45@users.noreply.github.com>`; commit
   messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and nothing else (no session links);
   the repo does not mention any other project. Before every push: scan `git log -p` for e-mail addresses, session
   links and local paths.

## Build loop

**Orchestrator:** one session; plans and builds nothing itself; starts planning, build and review agents; keeps
only plans, summaries and gates in context; keeps `.planning/STATE.md` and `.planning/loop/HANDOFF.md` current.

**Model per task, always the lightest that is safe:**

| Task | Model |
|---|---|
| renames, docs, tests from a template, lint fixes, summary formatting | haiku |
| implementation from a plan, tests, adapters, migrations, UI from a contract | sonnet |
| planning, architecture, reviews, security, privacy, access rules | opus |

**Branches and worktrees:** `loop/<BLOCK>`, one worktree per block outside the repo. No `pip install -e` and no
global installs from a worktree; code is loaded from the tree's own `src/` (pytest `pythonpath`, `PYTHONPATH=src`).

**Commits and push:** build agents commit small and thematic on `loop/<BLOCK>`; after a passed gate the
orchestrator merges to `main` (`--no-ff`) and pushes. Never `--force`, never secrets. Every merge to `main` needs
`./scripts/check.sh` green on the merged tree; from block B3 on, `check.sh` includes the eval and fails if it
exits non-zero.

**Stop only for the human's decisions** (scope, numbers, prices, legal, credentials, irreversible or outward-facing
actions, budget). Everything else: decide, and list it in the gate under "Decisions I made".

**Budgets:** pause at 5-hour usage 88 %, no new build agents at weekly usage 92 %, at most 2 local agents, no cloud
sessions. At about 40 % context: clean pause point, update STATE and HANDOFF, tell the human.

## Review gate (`.planning/<BLOCK>/REVIEW.md`, also at the top of `.planning/loop/FOUNDER_REVIEW.md`)

Sections: verdict, what works now, proof, findings (blockers / should / could), hard rules per rule, decisions I
made, what to check yourself, what to do yourself, open questions, risks and rollback, backlog. The human answers
"ok" / "ok, but <point>: <change>" / "no: <reason>".

## Definition of done

1. All must-requirements of the block implemented; acceptance criteria checkable.
2. `./scripts/check.sh` green; new logic tested including error paths.
3. Evals not worse than before the block; on merge the block is marked finished in `evals/config.json` and
   baselines are rewritten (worse only with a stated reason).
4. CLI changes run by hand on the golden path and one error path.
5. README and `.planning/STATE.md` updated.
